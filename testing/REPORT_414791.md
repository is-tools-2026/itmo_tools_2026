## 1 Цели и задачи тестирования

Я проверил API кофейни через Bruno: отправлял HTTP-запросы, сравнивал коды ответа и JSON с ожидаемыми результатами. Цель - убедиться, что сервер считает заказ, выбирает напиток, выдаёт пароль и чек, а неправильные данные возвращают ошибку 400 вместо сбоя сервера.

## 2 Описание продукта

testing/server.py - сервер Flask, который вызывает функции Coffee/coffee.py. Все четыре эндпоинта уже были в исходнике. Я дополнил их проверками и написал запросы с тестами Bruno. Это продвинутый вариант лабы вместо основного задания с unittest.

## 3 Область тестирования

POST /api/order-total - сумма заказа; GET /api/most-expensive - самый дорогой напиток; GET /api/wifi-password - пароль Wi-Fi; POST /api/receipt - чек. Для успешных запросов ожидаю 200 и нужные данные. Для неправильного ввода ожидаю 400 и непустое строковое поле error в JSON.

## 4 Стратегия тестирования

В коллекции 16 запросов. У каждого две проверки: HTTP-статус и содержимое JSON. Проверил обычный и нулевой заказ, цену с копейками, отрицательное и дробное количество, отсутствие поля, массив вместо объекта, пароль по умолчанию и длиной 12, слишком короткую и неправильную длину, обычный чек, неизвестный напиток, bool вместо количества и строку вместо JSON-объекта.

Запустил ту же коллекцию сначала на сервере из коммита 6cb8586, затем на исправленном сервере. В обоих запусках использовался уже исправленный coffee.py из основной версии работы. Поэтому результаты ниже показывают ошибки HTTP-слоя, а не повторяют старый запуск 53 unit-тестов.

Проверял через настоящий Bruno CLI 4.3.0 и работающий сервер на http://localhost:8000. В GUI Bruno коллекцию можно открыть из testing/bruno/coffee-api и выбрать окружение Local. Настольное приложение в этой проверке не использовал.

## 5 Критерии приёмки

Все четыре эндпоинта проверены. Количество - целое число от нуля; bool и дробное количество отклоняются. Цена сохраняет копейки и проверяется функцией calculate_order_total. Ошибки входных данных не должны превращаться в HTML-ответ 500. Пароль имеет заданную длину и содержит строчную букву, заглавную букву и цифру. Чек содержит правильные название, количество и сумму. Все запросы коллекции должны пройти.

## 6 Ожидаемые результаты

Подготовил коллекцию .bru, окружение Local, исправления сервера и протоколы before.json / before.txt и after.json / after.txt. Итоговый HTML-отчёт Bruno лежит в testing/reports/414791/after.html. Числа собраны в summary.json. Старые unit-тесты оставил как дополнительную проверку.

## 7 Найденные баги

1. Сервер преобразовывал цену через int: цена 10.1 превращалась в 10, а итог трёх напитков - в 30 вместо 30.3.

2. Отрицательное количество доходило до coffee.py, но ValueError не перехватывался. Клиент получал HTML и 500 вместо JSON и 400.

3. Дробное количество 1.5 молча превращалось в 1. Сервер принимал заказ вместо ошибки.

4. Для length=abc Flask подставлял значение по умолчанию 8. Неправильный параметр выглядел как успешный запрос.

5. В чеке quantity=true превращалось в 1 из-за int(True). Сервер принимал логическое значение как количество.

6. JSON-строка вместо объекта в запросе чека вызывала AttributeError при data.get(). В ответ приходила HTML-ошибка 500.

## 8 Исправления

Убрал int() для количества и цены из POST-запросов. Передаю значения в уже проверенные функции coffee.py: так сохраняются копейки и отклоняются дробное количество и bool. Перенёс расчёт в try/except, чтобы ValueError возвращался клиенту как JSON с кодом 400.

Добавил read_json_object(): тело запроса должно быть корректным JSON-объектом. Отдельно обрабатываю отсутствие обязательных полей. Длину Wi-Fi разбираю явно, неправильное значение не заменяется на 8. Для пустого меню тоже возвращаю JSON с ошибкой. Обновил пример формата чека в описании сервера.
