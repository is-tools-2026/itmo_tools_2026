# План и отчет по тестированию модуля кофейни (coffee.py)

## 1. Цели и задачи тестирования
Цель тестирования - проверка работы функций модуля вузовской кофейни `coffee.py`, поиск логических ошибок в расчетах и проверка реакции программы на некорректные входные данные.
Задачи:
- Написать автоматические unit-тесты с помощью модуля `unittest` для каждой функции.
- Проверить граничные случаи: нули, отрицательные числа, пустые строки, пробелы, несуществующие напитки и неверные типы данных (`int`, `list`, `None`, `bool`).
- Исправить найденные баги, добавить обработку исключений и провести повторный запуск тестов.

## 2. Описание тестируемого продукта
Модуль `Coffee/coffee.py` отвечает за работу заказа в вузовской кофейне. В нем находятся словарь напитков `MENU`, словарь скидочных промокодов `DISCOUNTS` и функции для получения цены напитка, подсчета стоимости заказа, поиска самого дорогого напитка, генерации пароля от Wi-Fi, печати чека и применения скидок.

## 3. Область тестирования
Тестируются все функции из модуля `coffee.py`:
1. `get_price(drink_name)` - возвращает цену напитка из меню.
2. `calculate_order_total(quantity, price)` - считает общую стоимость заказа.
3. `get_most_expensive_drink()` - находит самый дорогой напиток в меню.
4. `generate_wifi_password(length)` - генерирует пароль для Wi-Fi заданной длины.
5. `format_receipt(drink_name, quantity)` - формирует строку с чеком для покупателя.
6. `apply_discount(total, discount_code)` - считает сумму заказа со скидкой по промокоду из `DISCOUNTS`.

## 4. Стратегия тестирования
Применяется модульное (unit) тестирование на базе класса `unittest.TestCase`:
- Позитивные проверки на нормальных данных с помощью `assertEqual`, `assertAlmostEqual`, `assertTrue`, `assertFalse`, `assertIn`.
- Негативные проверки и граничные условия с помощью `assertRaises(ValueError)` и `assertRaises(TypeError)`.

## 5. Критерии приемки
- Каждая функция из `coffee.py` покрыта позитивными и негативными unit-тестами.
- При неверном типе аргументов выбрасывается `TypeError`, а при недопустимых значениях (нули, минусы, пустые строки, неизвестные напитки) выбрасывается `ValueError`.
- Все 16 написанных тестов успешно проходят (`OK`).

## 6. Ожидаемые результаты
Ожидается обнаружение дефектов при первичном прогоне тестов на исходном коде `coffee.py` и полное прохождение всех 16 тестов после внесения исправлений и добавления проверок.

## 7. Найденные баги (при первом запуске тестов)
При запуске команды `python -m unittest test_coffe.py -v` на исходном коде из 16 тестов прошло только 5, а 11 тестов завершились с ошибками (`FAILED (failures=7, errors=4)`). Выявлены следующие баги:
1. В функции `get_most_expensive_drink()` вместо `max()` использовалась функция `min()`, из-за чего вместо самого дорогого напитка (`latte`, 280 руб.) возвращался самый дешевый (`tea`, 120 руб.).
2. В функции `calculate_order_total(quantity, price)` вообще не было проверки типов и отрицательных/нулевых значений: при передаче строки вместо числа (`calculate_order_total("latte", 5)`) функция умножала строку и возвращала `"lattelattelattelattelatte"`, а также пропускала нули, отрицательные числа и булевы значения `True`/`False`.
3. В функции `get_price(drink_name)` не проверялся тип аргумента (на число `123` выдавался `ValueError` вместо `TypeError`, а на список `["latte"]` происходило падение программы), а также не учитывались пробелы по краям и заглавные буквы (`"  Latte "`).
4. В функции `generate_wifi_password(length)` при передаче `True` (так как `bool` в Python наследуется от `int`) выбрасывался `ValueError` вместо `TypeError`.
5. В функции `format_receipt(drink_name, quantity)` выводился заголовок `---Чек Coffee---` вместо указанного в описании функции `Чек CampusCoffee`, не проверялся тип `drink_name` на строку и пропускались отрицательные/нулевые значения количества.
6. Словарь промокодов `DISCOUNTS` в начале файла никак не использовался - отсутствовала функция применения скидки `apply_discount`.
7. В конце файла `coffee.py` вне блока `if __name__ == "__main__":` находились отладочные вызовы `print()`, которые засоряли консоль при импорте модуля в тесты.

## 8. Исправления
1. В `get_most_expensive_drink()` функция `min` заменена на `max(MENU, key=MENU.get)`.
2. В `calculate_order_total`, `generate_wifi_password` и `format_receipt` добавлены проверки типов (включая отсев `isinstance(..., bool)`) с выбросом `TypeError`, а также проверки `quantity <= 0` и `price <= 0` с выбросом `ValueError`.
3. В `get_price` добавлена проверка `isinstance(drink_name, str)` и обработка строки через `.strip().lower()`.
4. В `format_receipt` заголовок чека исправлен на `Чек CampusCoffee`.
5. Дописана функция `apply_discount(total, discount_code)` для работы со словарем `DISCOUNTS`.
6. Из конца файла `coffee.py` убраны лишние вызовы `print()`.

## 9. Повторный запуск тестов
После исправления кода выполнен повторный запуск `python -m unittest test_coffe.py -v`.
Результат: запущено 16 тестов, все 16 тестов прошли успешно (`Ran 16 tests - OK`).

## 10. Выводы
В ходе работы были изучены принципы модульного тестирования в Python с помощью пакета `unittest`, найдены и устранены 7 логических и типовых ошибок в коде кофейни, добавлена обработка исключений `ValueError` и `TypeError`, а также проведено взаимное ревью кода через Pull Request.
